# Audit Log — журнал входов и изменений Redmine, скрытый от администраторов

Плагин для Redmine 6.0+ (писался по исходникам 7.0.2).

## Что записывается

**Вход** (локальные пароли и LDAP):

- успешный вход, неудачный вход (с введённым логином и причиной), пароль верный, но ждём код 2FA, неверный код 2FA;
- выход и конец сессии (истекла, учётку заблокировали);
- попытки, отклонённые другими плагинами (например, `redmine_login_attempts_limit`), с текстом, который увидел пользователь;
- для каждой записи: время, IP, браузер, способ входа (`local` или `LDAP: <имя источника>`).

**Изменения**, которых нет в стандартных «Действиях»:

- все запросы на изменение (POST, PUT, PATCH, DELETE) к настройкам, пользователям, группам, ролям, трекерам, статусам,
  рабочим процессам, настраиваемым полям, источникам LDAP, проектам (настройки, модули, участники), версиям,
  перечислениям, репозиториям, запросам; сброс пароля, регистрация, изменения через API;
- по каждому запросу: кто, IP, действие (`users#update`), адрес, код ответа, параметры (пароли, ключи и токены вырезаны);
- **было → стало** по изменённым записям (пароль, соль и ключ 2FA показываются только как «изменено»);
- удаление задач, вложений, вики-страниц, трудозатрат, комментариев, новостей, сообщений и документов, даже если само
  действие обычное.

Изменения, которые и так видны в «Действиях» или в истории задачи (правка задач, комментарии, вики, трудозатраты,
наблюдатели), по умолчанию не записываются. Включаются через `log_routine: true`.

**Сам журнал**: каждое открытие, просмотр, выгрузка, проверка целостности и каждая неудачная попытка открыть.

**Тревоги** (подсвечиваются, счётчик за 7 дней):

- кто-то, кроме самого аудитора, изменил учётку аудитора: пароль, почту, способ входа, 2FA, статус, права;
- неверный пароль при открытии журнала, превышен лимит попыток;
- попытка открыть журнал человеком не из списка, в том числе админом;
- проверка целостности нашла нарушения.

## Как защищён доступ

- **Настройки лежат в файле на сервере** (`/opt/redmine/config/audit_log.yml`), а не в базе. В вебе их не видно и не изменить.
- **Открыть журнал могут только логины из списка в файле.** Остальным, включая администраторов Redmine, страница
  отвечает «не найдено». Ссылок на журнал нигде нет.
- **Для открытия нужны два пароля:** свой пароль Redmine (для LDAP-учёток проверяется через LDAP) и пароль журнала.
  В файле хранится только его хеш (PBKDF2-SHA256, 600 000 итераций). Даже захватив учётку аудитора, админ без пароля
  журнала ничего не увидит. После 5 неудачных попыток за 15 минут открытие блокируется.
- Журнал открывается на 15 минут (`unlock_minutes`), его можно закрыть кнопкой.
- **Удалять и править записи в интерфейсе нельзя.** Модель запрещает изменение, старые записи стираются только по
  сроку (`retention_days`).
- **Цепочка хешей:** каждая запись содержит хеш предыдущей. Если запись изменить в базе или удалить из середины,
  кнопка «Проверить целостность» (или `rake redmine:audit_log:verify`) покажет, где цепочка нарушена.

### Ограничения

- Против того, у кого есть **root или доступ к базе**, защиты нет: он может стереть таблицу или подделать цепочку
  целиком. Цепочка делает правку **заметной**, но не невозможной. Удаление самых новых записей с конца цепочка тоже
  не покажет. Чтобы это заметить, аудитор может время от времени записывать номер и хеш последней записи (они есть
  в CSV).
- Записываются только веб-запросы. Изменения из консоли и rake-задач (это доступно только тому, у кого есть SSH)
  не записываются.
- Дампы базы (`backup_pgsql`) содержат и журнал: доступ к ним равен доступу к журналу.

## Установка

Сначала узнайте, где Ruby и bundle (в `PATH` у root их нет):

```bash
systemctl cat redmine | grep -E 'ExecStart|Environment|WorkingDirectory'
# дальше RUBY_BIN — папка, где лежат ruby и bundle, например /usr/local/rbenv/versions/3.3.6/bin
```

```bash
cd /opt/redmine/plugins
git clone https://github.com/man-from-podolsk/redmine_audit_log.git
chown -R www-data:www-data redmine_audit_log

# Таблица журнала
cd /opt/redmine
sudo -u www-data env PATH="$RUBY_BIN:$PATH" RAILS_ENV=production \
  bundle exec rake redmine:plugins:migrate NAME=redmine_audit_log

# Пароль журнала (минимум 12 символов, вводится без эха)
$RUBY_BIN/ruby plugins/redmine_audit_log/bin/audit_log_password
# то же без Ruby:
python3 -c 'import hashlib,os,base64,getpass; p=getpass.getpass(); s=os.urandom(16); i=600000; h=hashlib.pbkdf2_hmac("sha256",p.encode(),s,i); print(f"pbkdf2_sha256${i}${base64.b64encode(s).decode()}${base64.b64encode(h).decode()}")'

# Настройки: только root пишет, Redmine читает, остальные не видят
cp plugins/redmine_audit_log/config/audit_log.yml.example config/audit_log.yml
nano config/audit_log.yml        # auditors, password, mount_path
chown root:www-data config/audit_log.yml
chmod 640 config/audit_log.yml

systemctl restart redmine
```

Журнал открывается по адресу `https://<redmine>/<mount_path>`. Записывать события плагин начинает сразу после
перезапуска, даже если файла настроек ещё нет.

Изменения в `audit_log.yml` подхватываются без перезапуска, кроме `mount_path`.

## Обслуживание

```bash
# Проверить цепочку из консоли (код выхода 1, если нарушена)
sudo -u www-data env PATH="$RUBY_BIN:$PATH" RAILS_ENV=production bundle exec rake redmine:audit_log:verify
# Удалить записи старше retention_days (это делается и само, раз в сутки)
sudo -u www-data env PATH="$RUBY_BIN:$PATH" RAILS_ENV=production bundle exec rake redmine:audit_log:purge
```

Удаление плагина: `rake redmine:plugins:migrate NAME=redmine_audit_log VERSION=0` (удалит таблицу с журналом), затем
убрать папку и перезапустить Puma.

## Проверка после установки

1. Под аудитором открыть `/<mount_path>`: просит два пароля. Неверный пароль даёт тревогу в журнале.
2. Под админом не из списка открыть `/<mount_path>`: «страница не найдена», в журнале тревога «попытка открыть без доступа».
3. Войти локальной учёткой, LDAP-учёткой, с неверным паролем, с несуществующим логином: всё в журнале с причиной
   и способом входа.
4. Учётка с 2FA: события «пароль верный, ждём код 2FA» и «успешный вход»; неверный код тоже записан.
5. Изменить настройку (например, заголовок приложения): запись `settings#edit` с «было → стало».
6. Изменить пользователя (права админа, почту) и сменить пароль: изменения видны, пароль только как «изменено».
7. Админом изменить учётку аудитора: запись с пометкой «ТРЕВОГА».
8. Удалить задачу: запись `issues#destroy`.
9. Поправить задачу: записи нет (при `log_routine: false`).
10. «Проверить целостность»: цепочка цела. Затем в базе поменять поле одной записи
    (`UPDATE audit_log_entries SET message='x' WHERE id=...`): проверка показывает эту запись.
11. Выгрузить CSV: в журнале запись «выгрузка CSV».
12. `chmod 644 config/audit_log.yml`: в журнале предупреждение о правах. Вернуть `640`.

## Обновление

Раз в сутки модуль сверяет свою версию с GitHub и, если есть новая, показывает уведомление внутри журнала (видят только аудиторы): что изменилось
(из `CHANGELOG.md`) и как обновить. Запрос идёт с сервера Redmine на `api.github.com` и `raw.githubusercontent.com`
в фоне и не замедляет страницы. Проверить сразу: `bundle exec rake redmine:audit_log:check_update RAILS_ENV=production`.

Если модуль установлен копированием:

1. Скачайте архив https://github.com/man-from-podolsk/redmine_audit_log/archive/refs/heads/main.zip.
2. Переименуйте старую папку: `mv plugins/redmine_audit_log /root/redmine_audit_log.old`.
3. Распакуйте архив в `plugins/redmine_audit_log` (папка в архиве называется `redmine_audit_log-main`, её нужно переименовать),
   `chown -R www-data:www-data plugins/redmine_audit_log`.
4. Если в `CHANGELOG.md` для новой версии сказано «миграция», выполните
   `bundle exec rake redmine:plugins:migrate NAME=redmine_audit_log RAILS_ENV=production`.
5. Перезапустите Redmine.

Если установлен через `git clone`: `cd plugins/redmine_audit_log && git pull` и перезапуск. Уведомление в этом случае
считает новые коммиты, а не версии.
